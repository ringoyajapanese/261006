# KOTOBA

한국어 사용자를 위한 일본어 쉐도잉 및 AI 일본어 멘토 앱. React + TypeScript + Vite로 구현한 백엔드 없는 앱입니다.

## 실행

Node.js 20.19+ 또는 22.12+에서:

```sh
npm install
npm run dev
```

브라우저에서 http://localhost:5173 을 엽니다. `npm run typecheck`, `npm test`, `npm run build`로 검증합니다. 빌드 결과는 `dist/`에 생성됩니다. 배포는 수행하지 않았습니다.

## 사용

4개 상황의 12개 문장에 일본어 원문, 읽기, 한국어 뜻을 제공합니다. 속도는 0.7× / 0.85× / 1.0× / 1.2×이며, 반복을 켜면 1초 간격으로 총 3번 듣습니다. 녹음 시작 버튼을 눌러 마이크를 허용하고, 녹음 완료 후 내 녹음을 재생합니다. 60초가 되면 자동 종료됩니다. 권한 요청·녹음·마무리 중에는 상황 및 문장 이동이 잠깁니다.

## 환경 및 제한

- 마이크는 **HTTPS 또는 localhost**에서만 동작합니다. 같은 네트워크의 모바일에서 HTTP IP 주소로 접속하면 녹음할 수 없습니다. 모바일 테스트는 HTTPS에서 진행하세요.
- Web Speech API의 일본어 음성은 OS/브라우저의 설치된 음성에 따라 품질이 달라집니다. 일본어 음성을 설치하면 도움이 됩니다. 음성 목록의 지연 로딩을 처리하고, 실패 또는 미지원 시 안내합니다. 실제 출력 언어·품질은 기기에서 확인해야 합니다.
- 음성 엔진 자체가 네트워크를 사용할 수 있습니다. 쉐도잉 기능에는 외부 API나 API 키가 필요하지 않습니다. AI 멘토를 이용할 때만 사용자가 입력한 키로 Gemini API를 호출합니다.
- MediaRecorder 코덱은 브라우저 지원에 따라 선택합니다. 녹음 파일은 메모리의 임시 Object URL로만 제공하며 업로드하거나 영구 저장하지 않습니다. 새 녹음, 문장 이동, 새로고침 또는 페이지 종료 시 삭제됩니다.
- 자동 발음 점수나 AI 음성 평가는 없습니다. 쉐도잉은 직접 듣고 비교하며, AI 멘토는 텍스트 문장을 설명·교정합니다.
- 테스트는 브라우저 API 모의 객체로 반복·취소·비동기 충돌·마이크 해제를 확인합니다. 실제 스피커 출력, 기기 권한 UI, 마이크 소리 및 코덱은 별도의 실제 기기 검증이 필요합니다.

## 구조

- `src/data.ts`: 안정적인 ID를 가진 상황·문장 데이터
- `src/App.tsx`, `src/styles.css`: 접근 가능한 반응형 학습 화면
- `src/audio/speech.ts`, `src/hooks/useSpeech.ts`: 반복 음성 및 취소 관리
- `src/hooks/useRecorder.ts`: 권한 요청, 녹음, 타이머 및 리소스 정리
- `src/ai/gemini.ts`, `src/components/AiMentor.tsx`: Gemini 요청과 AI 일본어 멘토 화면

## GitHub 및 배포

이 폴더의 소스를 GitHub 저장소에 올립니다. `node_modules/`와 `dist/`는 올리지 않습니다. `package-lock.json`은 반드시 포함합니다.

Netlify에서 GitHub 저장소를 연결하고 다음 설정으로 배포하세요. `netlify.toml`에도 같은 설정이 포함되어 있습니다.

- Build command: `npm run build`
- Publish directory: `dist`
- Node.js: `22`
- 배포 환경변수: 필요 없음 (AI 멘토는 사용자별 Gemini API 키 입력)

Netlify가 제공하는 HTTPS 주소에서는 마이크 권한을 요청할 수 있습니다. 실제 기기에서 일본어 음성과 녹음을 확인하세요.

## AI 일본어 멘토

- 모델: `gemini-3.5-flash-lite`. 모델은 자동으로 다른 모델로 변경하지 않습니다.
- 앱의 **AI 일본어 멘토**에서 [Google AI Studio](https://aistudio.google.com/api-keys)의 API 키를 입력하고 질문을 보냅니다. 문장 교정, 문법·뉘앙스 설명, 현재 예문을 활용한 대화를 요청할 수 있습니다.
- REST `generateContent`를 브라우저에서 Google에 직접 호출합니다. API 키는 URL이나 프롬프트 대신 `x-goog-api-key` 헤더에 전달합니다. 추가 SDK나 백엔드는 사용하지 않습니다.
- API 키와 대화는 React 메모리에만 보관합니다. 로컬/세션 스토리지, 쿠키, 서버, GitHub에 저장하지 않습니다. 키 지우기와 대화 지우기를 제공하며 페이지 새로고침·종료 시 초기화됩니다. 사용자 키는 브라우저에서 사용하므로 사용자 기기의 개발자 도구에서 확인할 수 있습니다.
- 보내기를 누를 때 질문, 최근 10회 대화, 현재 예문이 Google에 전송됩니다. 녹음은 보내지 않습니다. Google의 데이터 처리 정책과 키의 요금제/할당량이 적용됩니다.
- 취소, 키 변경, 대화 삭제 및 화면 종료 시 진행 중인 요청을 취소하고 오래된 응답을 무시합니다. 응답은 최대 60초 동안 기다립니다. 오류 발생 시 질문을 남겨 사용자가 직접 재시도할 수 있게 합니다. 요청 취소가 이미 발생한 Google의 처리/과금을 되돌리지는 않습니다.
- 키·권한 오류, 모델 미지원, 요청 한도, 네트워크 실패, 빈 응답, 안전성 차단, 응답 시간 초과를 안내합니다. AI 답변은 정확성을 보장하지 않으며 실제 음성 평가 기능은 아닙니다.
- 실제 API 검증에는 사용 가능한 키와 모델 접근 권한이 필요합니다. 키 없이 수행한 모의 테스트를 실제 Gemini 응답 검증으로 보고하지 않습니다.
- 공식 문서: [모델](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite), [REST API](https://ai.google.dev/api/generate-content).

### Vercel

GitHub 저장소의 `main` 브랜치를 연결하고 Framework Preset **Vite**, Build Command `npm run build`, Output Directory `dist`로 설정합니다. 운영자용 Gemini 키나 `VITE_*` 키 환경변수를 만들 필요가 없습니다. 사용자들이 페이지에서 각자 키를 입력합니다. 저장소가 연결되어 있다면 `main`의 새 커밋에 따라 Vercel이 다시 배포합니다.

## 검증 결과

- TypeScript 타입 검사와 프로덕션 빌드 통과.
- 자동 테스트 37개 통과 (쉐도잉 15개 + 멘토 22개): 콘텐츠·문장 이동, 반복 3회·1초 간격, 예약 재생 취소, 빠른 재생 클릭의 오래된 콜백 무시, 음성 목록 지연 로딩, 권한 오류 구분, 60초 자동 종료, 마이크 해제, Object URL 정리, 권한 요청 후 화면 종료 및 이전 녹음 콜백 충돌.
- Chromium에서 1440 / 800 / 390 / 320px 폭, 버튼 크기·화면 잘림, 200% 글자 확대, 키보드 포커스, 문장·상황 이동을 확인했습니다. 음성 설정 및 빠른 클릭은 브라우저의 모의 음성 API로 확인했습니다.
- 멘토 테스트는 인증 헤더·모델·문맥, API 오류, 답변 표시·후속 대화, 요청 취소·시간 초과·오래된 응답, 키 삭제·메모리 보관, HTML 안전 표시를 확인합니다.
- 실제 Gemini API 호출은 사용자 키가 없어 검증하지 않았습니다.
- 실제 일본어 음성 출력, 실제 마이크 권한 UI·녹음 소리·코덱, Safari·Firefox는 검증하지 않았습니다.
